# Switch Power のアーキテクチャ

コーディネーターはメインチャットで依頼を受け取ります。委任する場合は、現在のモデルカタログを起動ツールのスキーマと照合します。実行者と推論レベルを選び、作業範囲と同意を確認して、ネイティブツールでサブエージェントを起動します。結果の確認と返信は元のチャットで行います。

| コンポーネント | 役割 |
| --- | --- |
| [`skills/coordinate`](../plugins/switch-power/skills/coordinate/SKILL.md) | 実行者の選定、作業の調整、結果の確認。 |
| [`scripts/policy.py`](../plugins/switch-power/scripts/policy.py) | モデルの可用性、同意、作業範囲の検証。 |
| [`scripts/runtime.py`](../plugins/switch-power/scripts/runtime.py) | ネイティブカタログ、ローカルのタスク状態、検証用 CLI。 |
| [`hooks/guard.py`](../plugins/switch-power/hooks/guard.py) | Codex のイベント処理と `PreToolUse` による起動チェック。 |
| [`scripts/install.py`](../scripts/install.py) | グローバルインストール、無効化、アンインストール。 |
| [`scripts/configure.py`](../scripts/configure.py) | メインチャットのモデルの設定と復元。 |

## タスクの流れ

1. 短いローカル作業はコーディネーターが直接行います。委任する前に、準備、実行、結果確認にかかるコストと期待できる効果を比べます。明示的にサブエージェントを依頼された場合も、通常の同意確認を行います。
2. 委任する場合、CLI がタスクと作業範囲を登録します。Codex のスキーマで対応していれば、起動時にモデルと推論レベルを明示します。
3. Astra または `high` を超える推論レベルを使用する場合は、指定したモデル、推論レベル、作業範囲について同意が必要です。同意は現在のタスクに限り有効です。独立したタスクでは手順を最初から始めます。
4. コーディネーターはネイティブのライフサイクルを通じて結果を取得し、確認して返信します。`finish` でタスク状態を消去します。

メインモデルは Codex の設定で決まります。委任先はネイティブのサブエージェント起動パラメーターで選びます。次の依頼はメインチャットが受け取り、その都度判断します。

検証済みの Codex V2 スキーマでは、モデルと推論レベルの明示に `fork_turns: "none"` を使います。作業の指示には必要な文脈、制約、受け入れ条件を含めます。

## カタログと状態

インストーラーは `model/list` からカタログを取得します。委任の準備時に CLI が期限切れの情報を更新し、データの鮮度と起動スキーマとの互換性を確認します。

タスク状態はユーザー専用の一時ディレクトリに保存されます。作業範囲と最新の依頼を保持し、同意を該当する依頼にひも付けます。モデルカタログは Codex プロファイルに別途保存されます。[ランタイムのコマンドリファレンス](../plugins/switch-power/skills/coordinate/references/runtime.md)。

## トラブルシューティング

クローンまたは展開先で `python3 scripts/verify_native.py` を実行します。Windows では `py -3 scripts/verify_native.py` を使います。2 つのディレクトリでスキルの検出とフックの状態を確認します。必要なフックが `untrusted` の場合、Codex CLI の `/hooks` で定義を確認してください。ネイティブ起動が失敗した場合、コーディネーターが理由を示して利用可能な経路を選びます。

フックの適用範囲は Codex のツール呼び出し経路によって異なります。タスクの境界とユーザーの同意はコーディネーターが解釈します。[検証レポート](verification.ja.md)。
